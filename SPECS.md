## 1. Context

Central City is in danger again. Alchemy, using the Philosopher's Stone, is identifying people who
developed metahuman abilities in other timelines in order to restore their powers. Behind this operation
is Savitar, who needs to locate and coordinate these new metahumans.

Team Flash intercepted Alchemy's communications, but the information arrives **fragmented and
incomplete**. Cisco Ramon needs a system able to **rebuild the intercepted messages** and **determine the
location of Alchemy's lab**.

The system receives information from three surveillance devices placed at known points of Central City:

| Device            | Code             | Position (X, Y) |
|-------------------|------------------|-----------------|
| STAR Labs         | `star-labs`      | (-500, -200)    |
| CCPD              | `ccpd`           | (100, -100)     |
| S.T.A.R. Satellite| `star-satellite` | (500, 100)      |

Each device provides the **distance** to the lab and a **fragment** of the message sent by Alchemy.
Because of the interference generated by the Philosopher's Stone, some words may not be received; they
are represented as empty strings (`""`).

The information of the devices must be combined to obtain the lab position and rebuild the original
message.

## 2. Functional Requirements

| Code | Requirement |
|------|-------------|
| F1 | **Full processing** — receive the information of the three devices at once, determine the lab location by trilateration, rebuild the message and return both. |
| F2 | **Individual registration** — receive and register the information of each device independently (identification, distance, message fragment). Information may arrive in any order and at different moments, and is kept temporarily until there is enough information. |
| F3 | **Query and accumulated processing** — query the registered information and run the reconstruction operations over it. Return location and message when there is enough information; otherwise report that there is not enough data. |
| F4 | **Full replacement** — completely replace the information previously registered for a device (new distance **and** full message fragment) without affecting other devices. |
| F5 | **Partial update** — update the distance and/or the message fragment of a device; fields not provided keep their previous value. Not equivalent to F4. |
| F6 | **Deletion** — completely delete the stored information of one device without affecting the others. |

---

## 3. Considerations / Business Rules

| Code | Rule |
|------|------|
| BR01 | Device information may arrive independently and in any order. |
| BR02 | Received information is kept temporarily, **in memory**. No database, no external services. |
| BR03 | Empty fragments (`""`) are ignored during message reconstruction. |
| BR04 | Received information must be validated (distance present, finite and ≥ 0; message present, no `null` words). |
| BR05 | Errors for invalid, incomplete information or unknown devices must be handled properly. |
| BR06 | Update and delete operations must keep the stored information consistent. |
| BR07 | The domain must not depend on infrastructure details nor on HTTP. |
| BR08 | The code follows **Domain-Driven Design** and **Hexagonal Architecture (Ports and Adapters)**. |

---

## 4. Design Decisions (derived from the statement)

| Code | Decision |
|------|----------|
| DD01 | Devices are a closed catalog (enum). Names are accepted leniently: case-insensitive, ignoring non-alphanumeric characters (`"S.T.A.R. Satellite"`, `"star_satellite"`, `"star-satellite"` are equivalent). |
| DD02 | Fragments may have different lengths (transmission offset). They are **right-aligned**; leading positions with no word in any fragment are discarded as offset. |
| DD03 | Two different non-empty words in the same aligned position, or a position without any word, make the message undeterminable. |
| DD04 | Trilateration is solved analytically; the result must be consistent with the three distances within a tolerance of **1.0** unit. Coordinates are rounded to 2 decimals. |
| DD05 | Registering (F2) a device that already has a reading is a conflict — use F4/F5 to change it. Replacing/updating/deleting a device without a reading is "not found". |
